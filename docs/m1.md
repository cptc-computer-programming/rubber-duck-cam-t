# M1: Our First Homework Helper

**Milestone one is focused on making our application useful for a single homework assignment.**

We will work in three teams: Frontend, Backend, and Operations. Each team owns a different part of the system. Together, we will demonstrate a student getting useful help with a single assignment and show how we can tell whether the app is working.

**On this page:** [Shared goal](#shared-goal) · [Team goals](#team-goals) · [Architecture](#architecture) · [Technical references](#technical-references)

## Shared goal

**Our goal:** A student can start a session, recognize which assignment the duck supports and choose it, describe where they are stuck, and receive guidance that helps them decide what to try next.

The three teams will:

1. choose **one assignment together**
2. agree with the instructor on the kind of help the duck should provide
3. decide how to monitor and measure the success of the milestone.

## Architecture

### What is running now: M0

The repository currently contains deployment configuration and documentation. Docker Compose starts published Open WebUI and Ollama images. It does not yet build our own application source or start a monitoring stack.

```text
Student's browser
       |
       v
Open WebUI container (image)
  Chat interface + application backend
       |
       v
Ollama container (image) --> Language model on the server's GPU
```

### What we are working toward: M1

This is the planned architecture for M1.

```text
Student's browser
       |
       v
+--------------------------------------------------+
| Our build of Open WebUI                           |
|                                                  |
|  SvelteKit frontend                  TEAM 1       |
|       |  Chat requests                           |
|       v                                          |
|  Python / FastAPI backend            TEAM 2       |
|       ^                                          |
|       |  Assignment + coaching instructions       |
+-------|------------------------------------------+
        |  Model requests and responses
        v
  Ollama container --> Language model / GPU
  (image)

  Monitoring stack                    TEAM 3
  +----------------------------------------------+
  | Open WebUI sends HTTP metrics                |
  |   |                                          |
  |   v                                          |
  | OpenTelemetry Collector receives metrics     |
  |   |                                          |
  |   v                                          |
  | Prometheus collects and stores metrics       |
  |   |                                          |
  |   v                                          |
  | Grafana displays metrics from Prometheus     |
  +----------------------------------------------+
```

### How the components interact

| Component | What it does | How it connects |
| --- | --- | --- |
| SvelteKit frontend | Displays the assignment guidance, chat input, and responses. | Sends chat requests to the backend and displays the returned response. |
| Python/FastAPI backend | Handles application requests and supplies assignment context and coaching instructions. | Sends the conversation and instructions to Ollama; returns the generated response to the frontend. |
| Ollama | Loads and runs the language model. | Receives model requests from the backend and generates responses using the server's GPU. |
| OpenTelemetry Collector | Receives the HTTP metrics that Open WebUI already produces. | Accepts metrics from Open WebUI and exposes them in a format Prometheus can collect. |
| Prometheus | Collects and stores monitoring measurements over time. | Collects metrics from the Collector and makes them available for queries. |
| Grafana | Displays request volume, HTTP errors, and request duration over time. | Queries Prometheus to populate the dashboard. |
| Docker Compose | Defines and starts the containers and their connections. | Runs our application build, Ollama, and the monitoring services in the planned deployment. |

Frontend and Backend share one Open WebUI codebase. They can run as separate development processes while students edit code, then be packaged together in our Open WebUI container. We will continue using the published Ollama image.

Monitoring runs alongside the app. Chat messages do not pass through Grafana or Prometheus.
